# 前端各页面描述文档（用于重新设计参考）

> 本文档基于 `frontend/src` 现有实现整理，覆盖：各页面功能定位、关键交互细节、页面间关系，以及当前实现的缺陷/占位项。
> 目标读者：负责重新设计前端的产品与开发人员。凡标注 ⚠️ 处为当前实现的占位、死链或待办，重设计时应重点处理。

---

## 〇、总体架构：三端门户 + 统一骨架

系统按角色划分 **3 个门户**，共用一套主骨架（`MainLayout.vue`），通过薄壳布局注入不同菜单：

| 门户 | 覆盖角色 | 菜单 |
|------|----------|------|
| **患者端** | 患者 / 学生 / 护士 / 健康管理师 | 智能问答、我的健康档案、问卷记录 |
| **医生端** | 医生 | 智能问答、患者检索、药物查询、批量导诊、禁忌规则 |
| **管理员端** | 管理员 | 系统统计、用户管理、词条审核、禁忌规则、知识库、智能问答 |

- 路由守卫（`router/guards.ts`）：未登录 → `/login`（`/qa` 与 `/login` 本身免登录，支持游客问答）；登录后按角色加载对应布局。
- 菜单与角色映射的单一事实来源在 `config/menus.ts`；布局、顶栏、菜单高亮（子路径匹配 `/patients/:id` 也算激活）均从此读取。
- 设计令牌：主色 `#00478d / #005eb8`、表面 `#f8f9fa`、轮廓 `#c2c6d4`；组件圆角混用 `rounded-none`（卡片内）与 `rounded-full`（按钮/胶囊/头像）；图标统一 Material Symbols。

## 一、通用主骨架 `MainLayout`

三端共用的页面外壳，**三端外观高度一致**，仅侧边菜单与个别顶栏入口不同。

### 布局结构
- **侧边栏**（固定 260px，白底，右分隔线）：
  - 品牌区：`hub` 图标 + 品牌名（默认 "Clinical Precision RAG"）+ 副标题 "Clinical AI System"。
  - 导航区：分组标题「主菜单」，菜单项 = 图标 + 标题；激活项品牌蓝字 + 左侧 3px 蓝条 + 浅灰底。
  - 侧栏底部：当前角色徽标（`verified_user` + 角色中文名）。
- **顶栏**（sticky 4rem）：
  - 左：菜单折叠按钮（仅小屏显示）+ 标题 "Clinical Precision RAG"。
  - 右：通知铃铛按钮 → ⚠️ 仅弹 `暂无新通知`；用户头像（首字母圆形）→ 下拉菜单：
    - 患者端才有 **个人中心**（→ `/user`）；医生/管理员无此项。
    - **退出登录** → `ElMessageBox` 二次确认 → 清状态 → 回 `/login`。
- **内容区**：`<slot>` 承载各页面，默认 2rem 内边距。
- **底部栏**：© 版权 + 当前角色；右侧链接「系统状态 / 合规声明 / 隐私政策」→ ⚠️ 均为 `#` 死链。

### 响应式
- `<1024px`：侧栏变抽屉（transform 滑出），顶栏出现汉堡菜单按钮，遮罩点击关闭。

### ⚠️ 重设计注意点
- 三端共用一套壳，缺少端差异（患者端偏暖/医生端偏青/管理员偏深蓝等视觉区分）。
- 通知铃铛无真实业务；底部三链接为死链。

## 二、认证页（无布局外壳）

### 1. 登录 `/login`
- **功能**：账号密码登录。
- **交互**：
  - 居中玻璃卡片，标题 "IMKQAS 医疗知识智能问答系统"；用户名 + 密码（可切换明文）+「登录」按钮（loading 态）。
  - 支持 `?redirect=` 参数：登录成功后跳回来源页，否则 `/qa`。
  - 底部链接：**注册账号** → `/register`；**忘记密码？** → `/forgot-password`。
- **关系**：游客在 `/qa` 问答后登录时，游客会话自动合并进账号（见智能问答）。

### 2. 注册 `/register`
- **功能**：创建账户（注册即在后端建立患者身份档案）。
- **交互**（表单校验逐项拦截）：
  - 用户名：3-20 位字母/数字/下划线。
  - 手机号：`1[3-9]\d{9}`。
  - 密码：≥8 位且含大写+小写+数字；二次确认一致。
  - 真实姓名：必填（创建医生端可见的患者档案）。
  - 必须勾选同意「服务协议 / 隐私政策」。
  - 成功后 → `/login`。
- **关系**：注册建立的 identity 是患者端「我的健康档案」/「个人中心」和医生端「患者检索」的数据源头。

### 3. 忘记密码 `/forgot-password`
- **功能**：3 步重置密码向导（el-steps 步骤条：验证身份 → 重置密码 → 完成）。
- **交互**：
  - 步骤 1：手机号 + 验证码，「发送验证码」60s 倒计时。⚠️ 当前为 mock，未接真实短信 API。
  - 步骤 2：新密码 + 确认，「上一步 / 重置密码」。
  - 步骤 3：成功提示 +「立即登录」；底部「返回登录」。
- **关系**：→ `/login`。

## 四、患者端页面

### 1. 智能问答 `/qa`（全系统最复杂页面，三端均可见，功能随角色伸缩）
- **功能**：医疗问答 + 问卷智能评估的核心工作台，三栏布局。
- **布局与交互**：
  - **左栏·会话管理**：
    - 「会话管理」标题 +「新建咨询」按钮。
    - 会话列表（图标 + 标题）；底部入口：**回收站**（删除当前会话）、**词条审核**（仅管理员可见，打开右侧词条审核抽屉）、**帮助中心**。
  - **中栏·聊天区**：
    - 顶部医疗安全提示横幅。
    - 消息流：用户靠右 / AI 靠左；AI 身份标识 "PRECISION AI 临床决策支持"，思考动画，正文 `v-html` 渲染。
    - **5 种问卷卡片类型**：`suggestion`（建议）、`question`（单选题）、`completion`（填空题）、`safety_alert`（安全告警）、`manual_form`（手动表单兜底）。
    - 输入区：textarea（**Enter 发送**，兼容中文输入法 composition，300ms 防抖）；📎 附件按钮 ⚠️ 无功能；提示文案「支持 PDF 病历解析 · 实时检索临床指南」。
  - **右栏·知识检索路径**：展示本次问答的检索步骤（状态/耗时/颜色标识），超过 3 条可展开。
- **关键技术行为（重设计需保留的交互）**：
  - SSE 流式回答（`streamAsk`）；问卷走 `startLlmInterview` 流式对话。
  - 心跳每 60s；离开页面前 `beforeunload` 暂停问卷，支持断点续答。
  - **游客模式**：未登录可用，会话存 localStorage（有上限）；登录后自动同步游客会话到账号。
  - LLM 不可用时降级为手动表单（`manual_form` 卡 + `batchSubmit`）。
- **关联弹窗**：**详细评估报告** 对话框 —— 评估摘要 / 风险评估 / 详细分析 / 分层建议（即时建议、短期建议、专业资源、随访建议 / 免责声明）。
- **关系**：
  - → `/user`（患者端头像下拉「个人中心」）；
  - → `/login`（游客登录合并会话）；
  - → 词条审核抽屉（管理员）；
  - 问卷记录页「发起评估」跳回本页。

### 2. 个人中心 `/user`（患者端，顶栏头像下拉进入）
- **功能**：维护身份信息（姓名/性别/出生日期/证件号/地址/手机号），是健康档案与医生端检索的输入源。
- **交互**：
  - 「返回首页」返回链接。
  - Hero 卡：头像首字母 + 显示名 + 性别/年龄徽标 + 「患者档案: pat-{userId}」编号；「编辑资料」切换编辑态（编辑/取消/保存身份信息）。
  - 提示条：「保存后，医生端可通过姓名、证件号或手机号检索到您的身份信息」。
  - 身份卡（查看/编辑两态）：基本资料 —— 姓名、性别单选、出生日期日期选择、证件号（**6+4 掩码**显示）、地址、手机号（⚠️ 只读不可改）。
- **关系**：
  - → 健康档案页：身份字段在「我的健康档案」中**只读回显**；
  - 保存 → 医生端「患者检索」立即可检索。

### 3. 我的健康档案 `/profile`
- **功能**：维护五类病史标签（过敏史 / 慢性病史 / 用药史 / 手术史 / 家族病史），供更精准的问答与评估。
- **交互**：
  - 「基础信息」区：姓名/年龄/性别**只读**（来自个人中心）；未填身份时显示「请先到个人中心完善身份信息」+「去个人中心」。
  - 「医疗史」区：5 个病史卡（家族病史独占整行），每卡 = 标签列表（可点 `×` 删除）+ 输入框 + 添加按钮（Enter 或点击添加）；空显示「无记录」。
  - **固定底部操作条**：左「删除档案」（二次确认，危险红），右「保存档案」（保存中 loading）。删除后回空态。
  - 空态：图标 + 「您还没有健康档案」+「去创建」。
- **关系**：`/user`（身份入口）⇄ `/profile`（病史编辑）；医生端详情页「健康档案」Tab 展示同一份数据。

### 4. 问卷记录 `/records`
- **功能**：查看历史问卷与评估报告。
- **交互**：
  - 筛选栏：类型下拉（全部 / 心理健康(SAS/PHQ-9) / 基础健康状况 / 生活习惯评估）+ 时间排序切换（升/降）。
  - 记录卡片（可展开）：风险等级图标 + 标题 + 日期 + 得分 + 风险徽标；「查看详情」hover 浮现。
  - 展开态：**近 3 次得分趋势** 柱状图 + 较上次增减 N 分的差值徽标；可打开分析报告弹窗。
  - 空态：「发起评估」→ 跳 `/qa`。
- **关系**：⇄ `/qa`（发起评估）。数据来自问卷对话产生的评估结果。

## 五、医生端页面

### 1. 患者检索 `/patients`
- **功能**：按姓名 / 手机号 / 证件号检索患者。
- **交互**：
  - 页头统计框「系统患者总数」。
  - 检索卡：检索方式下拉（姓名/手机号/证件号）+ 关键词输入（按模式切换占位符），Enter 触发。
  - 结果表格：头像+姓名、性别+年龄徽标、脱敏手机号（`138****8888`）、脱敏证件号、「查看档案」hover 浮现；**整行点击 → `/patients/:id`**。
  - 仅「姓名」模式分页（10 条/页）；空态给「清除搜索条件」。
  - 进入页面默认加载总数 + 姓名检索第一页。
- **关系**：→ `/patients/:id`（行点击）。

### 2. 患者详情 `/patients/:id`
- **功能**：单个患者的完整临床视图，5 个 Tab + 右侧智能摘要。
- **交互**：
  - 顶部：「返回检索」+ Hero（头像、姓名、性别图标、年龄、患者编号、状态徽标（在管患者/随访中/新患者，由数据推断）、最近记录日期）+ 操作按钮：**新建问诊** → `/qa`、**打印报告** → `window.print()`。
  - Tab 1 **基本信息**：出生日期 / 联系电话 / 证件号码 / 家庭住址。
  - Tab 2 **健康档案**：基本资料 + 五类病史（chips 形式）。
  - Tab 3 **病情记录**：条件卡片（状态徽标 / 发病时间 / 描述）。
  - Tab 4 **检验与观察**：指标值 + 异常值**红色高亮**。
  - Tab 5 **问卷记录**：得分 + 按严重程度配色徽标。
  - **右侧 sticky「AI 智能摘要」**：由健康档案/病情/检验/问卷自动拼装，不随 Tab 切换消失。
- **关系**：由 `/patients` 进入；「新建问诊」→ `/qa`。

### 3. 药物查询 `/drugs`
- **功能**：药品检索 + 药品两两相互作用检测。
- **交互**：
  - 检索卡：药品名称输入 + 药品分类下拉（分类 onMounted 加载）。
  - 药品卡片网格：名称+副标题、分类徽标、**「有相互作用」**警示徽标、规格/厂商页脚。
  - **右上相互作用检测**：下拉勾选 ≥2 个药品即 `watch` 自动发起 `checkBatch`。
  - 卡片点击 → 详情弹窗：基本信息 8 字段 + 适应症/禁忌症/不良反应标签 + 用法用量/注意事项/储存条件。
  - 右侧 sticky 相互作用面板：药品对 + 类型徽标 + 描述/机制/建议。移动端有 FAB 回顶按钮。
- **关系**：独立工具页，无强跳转出口。

### 4. 批量导诊 `/triage`
- **功能**：批量输入多症状，一键获得各症状的分诊科室建议与急诊风险。
- **交互**：
  - 左栏（sticky）输入卡：症状行（编号、textarea 自适应高度、单条 ≤200 字、上限 20 条）、添加/移除行、「批量导诊」按钮。
  - 右栏结果：
    - **急诊风险横幅**：检测到 N 条急诊风险 + 最高等级徽标 + 警示文案与行动建议。
    - 单条失败 → 错误卡 +「重试」。
    - 结果卡：序号、症状原文、来源徽标、置信度/耗时、**推荐科室（置信度进度条 + 命中特征 chips + 推荐理由）**、建议文案。
    - 空态占位。
- **关系**：独立工具页。后端默认开启 `includeEmergencyCheck`（急诊风险检测随主查询一起返回）。

### 5. 禁忌规则 `/contraindication-rules`（医生端 + 管理员端共用菜单）
- **功能**：维护药物-人群禁忌规则库（增删改查 + CSV 批量导入）。
- **交互**：
  - 统计行：活跃规则总数+本月新增、禁用等级规则数、相对禁忌规则数；右侧「批量导入」「新增规则」。
  - 筛选栏：药物名称（400ms 防抖）、适用人群下拉、严重程度下拉（ABSOLUTE / RELATIVE / CAUTION / UNCLEAR）、「应用筛选 / 重置」。
  - 规则表格：药物名称+ATC、人群 pill、禁忌类型 pill、风险描述（**2 行截断**）、证据等级、最后更新、状态（已发布/审核中/草稿）、行尾编辑/删除图标按钮。
  - sticky 底部页码分页（含省略号逻辑）。
  - 新增/编辑弹窗：药物名称* / ATC / 人群名称* / 禁忌类型* / 证据等级 / 风险描述 / 来源。
  - 批量导入弹窗：CSV 格式提示 + 结果反馈。
- **关系**：管理员端另有「知识库 → 禁忌规则」Tab 与菜单入口重复（见知识库 ⚠️）。

## 六、管理员端页面

### 1. 系统统计 `/dashboard`
- **功能**：全局业务指标看板（ECharts）。
- **交互**：
  - 右上「刷新」。
  - 5 张统计卡：用户总数 / 文档总数 / 分诊请求数 / 待审核术语 / 今日已通过。
  - 4 张图表：用户角色分布（饼）、文档处理状态（饼）、热门分诊科室（横向条形）、紧急程度分布（**彩色条形：危急红 / 高危橙 / 中危青 / 低危绿**）。
  - 右列：性能指标卡（**分诊成功率环形图**（offset 251.2）+ 规则引擎/大语言模型平均耗时）、服务状态卡（QA / Triage 在线圆点 + 徽标）、**术语审查警报**卡（实际值 vs 阈值进度条 + 红色告警态 +「前往处理」→ `/term-review`）。
  - 模块级容错：`Promise.allSettled`，单个接口失败不影响整页；窗口 resize 处理、卸载时 dispose 图表。
- **关系**：→ `/term-review`（警报卡出口）。

### 2. 用户管理 `/users`
- **功能**：管理系统用户账号与角色。
- **交互**：
  - 页头 +「新增用户」。
  - 检索卡：关键词（用户名/手机号，Enter/清空触发）+ 角色下拉（全部 / 6 种角色，切换即回到第一页）。
  - 表格：用户（头像首字母 + 用户名）、脱敏手机号、角色徽标（管理员蓝 / 医生绿 / 其余灰）、创建时间、操作（**编辑 / 删除，hover 行才显示**）。
  - 底部：显示「N-M 条，共 X 位用户」+ 上一页/下一页（首页/末页禁用）。
  - 空态：「暂无匹配的用户」+ 清除筛选。
  - 新增/编辑弹窗：用户名*、手机号（11 位）、角色*、密码（新增必填 ≥6 位；**编辑留空则不修改**）；保存后刷新列表。
  - 技术说明：后端无角色筛选参数 → 前端按 `size=100` 循环拉全量，再本地过滤 + 本地分页。
  - 删除有二次确认（不可恢复）。
- **关系**：独立管理页。

### 3. 词条审核 `/term-review`
- **功能**：审核 LLM 从患者口语中抽取的未映射医学词条（标注为标准术语 / 拒绝），联动统计告警。
- **交互**：
  - 4 张统计卡：待审核数、未映射率（%）、今日已审核、告警状态（正常/告警中，红色左边框触发）。
  - 表格头：标题「待审核列表」+「批量通过」（**选中 ≥1 才可点**）。
  - 筛选栏：搜索框（词条/上下文/LLM猜测，400ms 防抖）+ 状态下拉（待审核/已通过/已拒绝/全部）+ 「共 N 条记录」。
  - 表格列：多选、口语表达、上下文、实体类型徽标（症状/药品）、LLM猜测、**置信度进度条**（≥85% 绿 / ≥60% 橙 / 低红）、频次、首次出现、**标准化操作列**（待审核行：标准术语输入框 + 通过/拒绝按钮；已处理行：已通过/已拒绝徽标）。
  - 页码式分页；选中行有高亮 + 左蓝条。
  - **批量标注弹窗**（Teleport 到 body）：提示已选 N 条 + 统一标准术语输入 + 确认/取消，成功后反馈「成功 X 条」。
- **关系**：⇄ `/dashboard`（警报卡进入/数据联动）；管理员端「知识库 → 词条审核」Tab 复用本组件；`/qa` 侧栏「词条审核」抽屉复用同一数据源（组件见下）。

### 4. 知识库 `/knowledge`
- **功能**：医学文档上传、向量化处理、预览与分块浏览。⚠️ 页面内含 3 个 Tab：**文档管理（默认）/ 禁忌规则 / 词条审核**（后两者直接复用 `ContraindicationRules` 与 `TermReview` 组件）。
- **交互（文档管理 Tab）**：
  - **左列**：
    - 分类管理侧栏：分类列表（名称 + 文档数），选中态高亮，点击过滤右侧文档；顶部 `add_circle` 按钮 ⚠️ 无事件。
    - 上传区：拖拽 / 点击选择，**仅 PDF、单文件 ≤50MB**，逐文件校验与上传；上传成功自动刷新列表。
  - **右列（上）文档列表卡**：
    - 搜索框（标题/内容）+「筛选器」按钮 ⚠️ 无功能 + 显示「1-N / 共 X 个文件」。
    - 表格：文档名称（PDF/文档图标）、大小 ⚠️（占位「未知大小」）、分类徽标、上传时间、**处理状态**（已完成向量化 / 正在处理(百分比) ⚠️ 占位 50% / 待处理）、操作下拉（**预览 / 删除 / 重新处理**）。
    - 选中行高亮；点击行 → 加载该文档的分块 + 预览。
  - **右列（下）分屏浏览**：
    - **文档预览**：PDF 用 Blob URL + iframe 渲染；文本用 `<pre>` 展示；未选中文档有引导占位；加载失败有「重试」。⚠️ 顶栏 放大/缩小/全屏 按钮无功能。
    - **向量分块浏览**：分块卡片（ID、分块 #n、可选相似度、内容截断 200 字、自动提取的医学关键词标签 ≤3 个）、点击选中（蓝框 + ✓）、底部操作栏（当前选中信息 + **复制** 全文 + **语义搜索** ⚠️ TODO 仅提示开发中）。
    - 无分块时：提示 +「进行分块处理」按钮。
  - 重新处理：二次确认 → 提交后**每 5s 轮询**状态，最多 60 次（5 分钟）超时提示。
- **⚠️ 重设计注意点**：
  - 入口重复：禁忌规则、词条审核既有独立菜单，又被知识库 Tab 收纳，两套入口并存。
  - 大小、进度为占位值；筛选器、缩放按钮、语义搜索未实现。

### 5. 词条审核抽屉 `TermReviewPanel`（组件，非路由页面）
- 嵌入 `/qa` 左栏「词条审核」（仅管理员可见）。
- 右滑抽屉（720px）：4 个精简统计卡 + 筛选栏（状态下拉、搜索、批量标注按钮带选中数）+ el-table（多选/口语表达/上下文/实体类型/LLM猜测/置信度着色/频次/首次出现/操作：标准术语输入 + 通过/拒绝）+ el-pagination（10/20/50）。
- 打开抽屉时刷新列表与统计；与 `/term-review` 页面共用 `adminService` 数据源。

## 七、页面间关系总览

```
游客/登录
  /login ──(redirect)──> /qa（游客会话登录后合并）
  /register ──> /login
  /forgot-password ──> /login
  顶栏退出登录 ──> /login

患者端
  /qa ⇄ /user（头像下拉进入；保存身份 → 供档案与医生端检索）
  /user → /profile（身份字段只读回显）
  /profile → /user（未填身份时的引导出口）
  /records → /qa（空态「发起评估」）
  /profile、/records、/user 均在患者端菜单内

医生端
  /patients → /patients/:id（行点击）
  /patients/:id → /qa（「新建问诊」）；→ window.print（打印报告）
  /drugs、/triage、/contraindication-rules 为独立工具

管理员端
  /dashboard → /term-review（警报卡「前往处理」）
  /users、/term-review、/knowledge、/contraindication-rules 独立菜单
  /knowledge 内 Tab 再次嵌入 禁忌规则 + 词条审核（入口重复 ⚠️）
  /qa（管理员）→ 词条审核抽屉（与 /term-review 同数据源）
```

### 数据联动主线
1. **身份链**：注册（realName）→ 个人中心身份 → 患者健康档案（只读回显）→ 医生端患者检索 → 患者详情。
2. **问卷链**：`/qa` 问卷对话 → 评估结果落库 → `/records` 记录与趋势图 → `/patients/:id` 问卷 Tab。
3. **审核链**：`/qa` 产生未映射词条 → `/term-review`（或抽屉）审核标注 → `/dashboard` 待审核/未映射率统计。
